# 一問一答ジェネレーター

渡された素材から知識を粒に分解し、`data/qa/cloudops.js` の `groups[].items` に追記する。
追記だけで完結する — **index.html / js/qa.js / js/dashboard.js / CSS を編集する必要はない**
(CSSのリビルドも不要)。

一問一答は**用語と判断基準を思い出すための場**。行をタップすると答えが開く、単語帳のような使い方をする。
シナリオを読んで選択肢から選ぶ演習は問題集(`data/quizbank/`)の役割、
仕組みを図と表で理解する場は特設ページ(`data/topics/`)の役割。**ここに長文を書かない。**

## 1件のかたち

```
Q: S3 Object Lockのコンプライアンスモードとは?
A: 保持期間中はrootユーザーを含む誰もオブジェクトを削除・上書きできないモードです。
   保持期間の短縮もモードの変更もできません。
   (任意)決め手: 「削除されてはならない」という例外を認めない要件は、このモードが答えになります。
```

- **問い(`q`)は60字以内**。「〜とは?」「AとBの違いは?」「〜するには?」「〜は◯◯できる?」の4型でほぼ書ける
- **答え(`a`)は1〜2文・140字以内**。答えを読んだだけで完結すること(「詳しくは〜参照」で逃げない)
- **`note` は任意**。試験でその知識をどう使うか(決め手)を1文で書けるときだけ足す。全部には付けない

## ワークフロー

### 1. 素材を知識の粒に分解する

問題1つから、たいてい**5〜8個の粒**が取れる。取り方:

- 問題文に出てきた**サービス・機能・モード・プロトコルの定義**(「〜とは?」)
- 正解と誤答を分けた**対比**(「コンプライアンスモードとガバナンスモードの違いは?」)
- 誤答の選択肢が**なぜ使えないか**(「S3バージョニングは削除を防げる?」→「防げません。…」)
- 手順・前提条件(「ピアリング接続を作成した後に必要な設定は?」)

**素材の問題文をそのまま設問にしない。** 一問一答は知識を問うものであって、シナリオを解かせる場ではない。
「ある企業が…」で始まる問いを書きたくなったら、それは問題集(`data/quizbank/`)向き。
なお問題集の問題文・選択肢は著作物なので、素材の文言をそのまま保存しない(知識に還元してから書く)。

### 2. 事実を確認する

**存在しないサービス名・機能名・制限値を書かない。** 素材の解説にも誤りや古い情報が混じる。
少しでも自信がない仕様は WebSearch / WebFetch でAWS公式ドキュメントを確認し、
確認できなかった数値・仕様は書かずに省く。答えが1〜2文と短いぶん、断定の重みが大きい。

既存教材(`data/cloudops/`)や特設ページ(`data/topics/`)に同じ用語があれば
`grep -ril "<キーワード>" data/` で確認し、**用語・訳語を揃える**。

### 3. 置き場所を決める

`data/qa/cloudops.js` の `groups` はテーマ単位。既存グループに合うならそこへ**追記**し、
合うグループがなければ新しいグループを足す(1グループ 5〜10問が目安)。

id は `qa-cloudops-<3桁連番>`。**セット全体を通した連番**で、既存の最大番号 + 1 から振る
(グループごとの連番ではない)。

### 4. データを書く

```js
{
  title: "S3のデータ保護",          // グループ名。テーマを短く(15字前後)
  domain: 4,                        // SOA-C03 の分野番号(下表)。バッジに「分野4」と出る
  topicId: "vpc-endpoint-types",    // 任意。関連する特設ページのid(実在するもののみ)
  items: [
    {
      id: "qa-cloudops-001",        // qa-<セットid>-<3桁連番>。セット内で重複させない
      q: "S3 Object Lockとは?",     // 問い(60字以内)
      a: "オブジェクトをWORMで保護し、…", // 答え(1〜2文、140字以内)
      note: "…",                    // 任意。試験での決め手を1文で
    },
  ],
}
```

`q` / `a` / `note` は**プレーンテキスト**。HTMLタグを書いてもエスケープされてそのまま表示される。
表・リスト・図が欲しくなったら、それは特設ページ向きの内容(topic-explainer スキル)。

**domain の割り当て**(SOA-C03 の公式分野。`data/quizbank/index.js` の `DOMAINS` と対応):

| # | 分野 | 典型トピック |
|---|---|---|
| 1 | モニタリング、ログ記録、分析、修復、パフォーマンスの最適化 | CloudWatch、X-Ray、メトリクス、アラーム |
| 2 | 信頼性と事業の継続性 | AWS Backup、スケーリング、マルチAZ、DR、Storage Gateway |
| 3 | デプロイ、プロビジョニング、オートメーション | CloudFormation、Systems Manager、AMI、タグ戦略 |
| 4 | セキュリティとコンプライアンス | IAM、KMS、Object Lock、監査、データ保護 |
| 5 | ネットワークとコンテンツ配信 | VPC、エンドポイント、ピアリング、Route 53、CloudFront |

セット末尾の `references` はセット全体の参考リンク(公式ドキュメントのみ)。
新しいテーマを足したら、その根拠にしたドキュメントを1本加える。

**文体**は docs/content-guide.md の「3. 文体・表記」に従う。日本語「です・ます」調、
サービス名は公式表記(AWS Lambda / Amazon SQS の接頭辞を間違えない。2025年以降の名称を使う)。

### 5. 検証する

```bash
node scripts/validate.js data/qa/cloudops.js
```

エラー0件にする(id形式・連番重複・必須項目・HTMLタグの混入・`topicId` の実在をチェックする)。
`q` が60字、`a` が140字を超えると警告が出る — **警告が出たら分割を検討する**。
1問に2つ以上の知識を詰めているサインであることが多い。

表示確認は `npm run serve` → http://localhost:4173/index.html の「CloudOps一問一答」。
追加した行をクリックして答えが開くこと、「すべて表示」で一覧できることを見る。

### 6. 報告する

最終応答で以下を伝える(本文は貼らない):

- 追加した問数と、置いたグループ(新規なら分野も)
- カバーした用語を列挙(1行)
- 事実確認のために参照した公式ドキュメント
- validate の結果

コミットは頼まれた場合のみ(commit-push スキルを使う)。

## 品質基準

- **答えが思い出せる粒度に切る。** 「AWS Backupとは?」に対して対応サービス・タグ割り当て・保持期間まで
  詰め込まない。3問に割る。
- **否定形の問いを活用する。** 「S3バージョニングは削除を防げる?」のような問いは、
  誤解をピンポイントで潰せるため一問一答と相性がよい。答えは「防げません。」から始める。
- **対比はセットで入れる。** 「Aとは?」を入れたら「Bとは?」または「AとBの違いは?」も入れる。
  試験は似たものの使い分けを問う。
- 既存の問いと重複していないか、追記前に `grep -n 'q: ' data/qa/cloudops.js` で一覧して確認する。
- 1グループが10問を超えたらテーマを分割する。

## 別の試験のセットを追加する場合

AI Practitioner など別試験の一問一答を作るときは、`data/qa/<id>.js` を新規作成して
`export const qaSet = { id, title, exam, description, groups, references }` を書き、
`data/qa/index.js` の `qaSetIds` に id を追加する。
ダッシュボードはセットごとにカードを並べるので、UI側の変更は不要。
