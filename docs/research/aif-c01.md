# AIF-C01 (AI Practitioner) 試験ガイド調査結果

調査日: 2026年8月14日。AWS公式の日本語版試験ガイド(バージョン 1.4 AIF-C01)を一次情報として確認した結果をまとめます。

## 試験概要(コード・問題数・時間・合格点・受験料)

| 項目 | 内容 |
|---|---|
| 試験名 | AWS Certified AI Practitioner |
| 試験コード | AIF-C01 |
| レベル | Foundational(基礎) |
| 問題数 | 65問(採点対象50問+採点対象外15問。採点対象外の設問は試験中に識別できません) |
| 試験時間 | 90分 |
| 合格スコア | 700点(100〜1,000の換算スコア。分野ごとの足切りはない補整スコアリングモデル) |
| 受験料 | 100 USD |
| 受験方法 | ピアソンVUEテストセンターまたはオンライン監督付き試験 |
| 対応言語 | 英語、日本語、韓国語、中国語(簡体字)ほか |
| 想定受験者 | AWSのAI/MLテクノロジーに最大6か月間携わった経験を持つ方(AI/MLソリューションを使用するが、必ずしも構築はしない) |

推奨されるAWS知識は、主要サービス(EC2、S3、Lambda、SageMaker)とそのユースケース、責任共有モデル、IAM、グローバルインフラストラクチャ(リージョン/AZ/エッジ)、料金モデルへの精通です。

### 対象範囲外のジョブタスク

以下は本試験の範囲外と明記されています(=問題を作る際も「実装・コーディングの詳細」ではなく「概念・選定・説明」を問う)。

- AI/MLモデルまたはアルゴリズムの開発・コーディング
- データエンジニアリング手法や特徴量エンジニアリング手法の実装
- ハイパーパラメータのチューニングまたはモデル最適化の実行
- AI/MLパイプラインまたはインフラストラクチャの構築とデプロイ
- AI/MLモデルの数学的または統計的分析の実施
- AI/MLシステムのセキュリティまたはコンプライアンスプロトコルの実装
- AI/MLソリューションのガバナンスフレームワークとポリシーの開発・実装

### 出題形式

公式ガイドに記載の5形式です。

- **択一選択問題**: 正しい選択肢が1つ、誤った選択肢(不正解)が3つ。
- **複数選択問題**: 5つ以上の選択肢のうち、正解が2つ以上。すべて正解を選択する必要がある。
- **並べ替え**: 3〜5つの答えのリストを正しい順序に並べる。
- **内容一致**: 3〜7つのプロンプトのリストと答えのリストをすべて正しく一致させる。
- **ケーススタディ**: 1つのシナリオに設問が2つ以上。設問ごとに個別採点。

未解答は不正解として採点されますが、推測による解答へのペナルティはありません。

> **本アプリへの反映方針**: 本アプリのクイズエンジンは択一(single)/複数選択(multiple)の2形式のため、並べ替え・内容一致・ケーススタディで問われる知識(例: MLパイプラインの順序、手法と用途の対応)は、択一・複数選択の形に変換して収録します。

## 出題分野と比率

日本語版公式試験ガイドの正式名称による5分野構成です。

| コンテンツ分野(公式日本語名称) | 比率 |
|---|---|
| 第1分野: AIとMLの基礎 | 20% |
| 第2分野: 生成AIの基礎 | 24% |
| 第3分野: 基盤モデルの応用 | 28% |
| 第4分野: 責任あるAIに関するガイドライン | 14% |
| 第5分野: AIソリューションのセキュリティ、コンプライアンス、ガバナンス | 14% |

生成AI関連(第2+第3分野)だけで52%を占めるのが最大の特徴です。

## 分野別のタスクステートメント詳細

### 第1分野: AIとMLの基礎(20%)

- **タスク1.1: AIの基本的な概念と用語を説明する**
  - 基本的なAI用語の定義: AI、ML、深層学習、ニューラルネットワーク、コンピュータビジョン、自然言語処理(NLP)、モデル、アルゴリズム、トレーニングと推論、バイアス、公平性、フィット、大規模言語モデル(LLM)
  - AI・ML・深層学習の類似点と相違点
  - 推論の種類(バッチ、リアルタイムなど)
  - AIモデルのデータタイプ(ラベル付き/ラベルなし、表形式、時系列、画像、テキスト、構造化/非構造化)
  - 教師あり学習、教師なし学習、強化学習
- **タスク1.2: AIの実用的なユースケースを特定する**
  - AI/MLが価値を提供できる応用分野(人間の意思決定の支援、スケーラビリティ、オートメーション)
  - AI/MLソリューションが適切でない場合(費用対効果の分析、予測ではなく特定の結果が必要な状況など)
  - ユースケースに適したML手法の判断(回帰、分類、クラスタリングなど)
  - 実際のAI応用例(コンピュータビジョン、NLP、音声認識、レコメンデーション、不正検出、予測)
  - AWSのマネージドAI/MLサービスの機能(SageMaker、Amazon Transcribe、Amazon Translate、Amazon Comprehend、Amazon Lex、Amazon Pollyなど)
- **タスク1.3: ML開発ライフサイクルについて説明する**
  - MLパイプラインの構成要素: データ収集、探索的データ分析(EDA)、データ前処理、特徴量エンジニアリング、モデルトレーニング、ハイパーパラメータチューニング、評価、デプロイ、モニタリング
  - MLモデルのソース(オープンソースの事前トレーニング済みモデル、カスタムモデルのトレーニング)
  - 本番環境でモデルを使用する方法(マネージドAPIサービス、セルフホストAPI)
  - MLパイプラインの各ステージに関連するAWSサービス(SageMaker、SageMaker Data Wrangler、SageMaker Feature Store、SageMaker Model Monitorなど)
  - MLOpsの基本概念(実験、反復可能なプロセス、スケーラブルなシステム、技術的負債の管理、本番稼働の準備、モデルモニタリング、モデルの再トレーニング)
  - モデルパフォーマンスメトリクス(正解率、ROC曲線下面積(AUC)、F1スコア)とビジネスメトリクス(ユーザーあたりのコスト、開発コスト、顧客フィードバック、ROI)

### 第2分野: 生成AIの基礎(24%)

- **タスク2.1: 生成AIの基本概念を説明する**
  - 基礎概念: トークン、チャンク化、埋め込み表現、ベクター、プロンプトエンジニアリング、トランスフォーマーベースのLLM、基盤モデル、マルチモーダルモデル、拡散モデル
  - ユースケース: 画像・動画・音声の生成、要約、チャットボット、翻訳、コード生成、カスタマーサービスエージェント、検索、レコメンデーションエンジン
  - 基盤モデルのライフサイクル(データ選択、モデル選択、事前トレーニング、ファインチューニング、評価、デプロイ、フィードバック)
- **タスク2.2: ビジネス上の問題解決に生成AIを使用する場合の可能性と限界を理解する**
  - メリット(適応性、応答性、シンプルさ)
  - デメリット(ハルシネーション、解釈可能性、不正確さ、非決定性)
  - 適切な生成AIモデルの選択要因(モデルタイプ、パフォーマンス要件、機能、制約、コンプライアンス)
  - ビジネス価値とメトリクス(クロスドメインのパフォーマンス、効率、コンバージョン率、ユーザーあたりの平均収益、正解率、顧客生涯価値)
- **タスク2.3: 生成AIアプリケーションを構築するためのAWSインフラストラクチャとテクノロジーについて説明する**
  - 開発用のAWSサービス: Amazon SageMaker JumpStart、Amazon Bedrock、PartyRock (Amazon Bedrock Playground)、Amazon Q
  - AWS生成AIサービスを使うメリット(アクセシビリティ、参入障壁の低さ、効率性、費用対効果、市場投入までのスピード、ビジネス目標の達成能力)
  - AWSインフラストラクチャの利点(セキュリティ、コンプライアンス、責任、安全性)
  - コストに対するトレードオフ(応答性、可用性、冗長性、パフォーマンス、リージョン展開、トークンベースの価格設定、プロビジョンドスループット、カスタムモデル)

### 第3分野: 基盤モデルの応用(28%)

- **タスク3.1: 基盤モデルを使用するアプリケーションの設計上の考慮事項を説明する**
  - 事前トレーニング済みモデルの選択基準(コスト、モダリティ、レイテンシー、多言語、モデルサイズ、複雑さ、カスタマイズ、入力/出力の長さ)
  - 推論パラメータの影響(温度、入出力の長さなど)
  - 検索拡張生成(RAG)の定義とビジネス活用(Amazon Bedrock、ナレッジベースなど)
  - ベクターデータベースに使えるAWSサービス: Amazon OpenSearch Service、Amazon Aurora、Amazon Neptune、Amazon DocumentDB (MongoDB互換)、Amazon RDS for PostgreSQL
  - 基盤モデルカスタマイズ手法のコスト面トレードオフ(事前トレーニング、ファインチューニング、状況に応じた学習(in-context learning)、RAG)
  - マルチステップタスクにおけるエージェント(Amazon Bedrockのエージェントなど)の役割
- **タスク3.2: 効果的なプロンプトエンジニアリング手法を選択する**
  - 概念と構成(コンテキスト、指示、ネガティブプロンプト、モデルの潜在空間)
  - 手法(思考の連鎖(Chain-of-Thought)、ゼロショット、シングルショット、フューショット、プロンプトテンプレート)
  - 利点とベストプラクティス(応答品質の向上、実験、ガードレール、発見、具体性と簡潔さ、複数のコメントの使用)
  - リスクと限界(露出、ポイズニング、ハイジャック、ジェイルブレイク)
- **タスク3.3: 基盤モデルのトレーニングとファインチューニングのプロセスを説明する**
  - トレーニングの重要な要素(事前トレーニング、ファインチューニング、継続的な事前トレーニング)
  - ファインチューニングの方法(指示のチューニング、特定の分野へのモデルの適応、転移学習、継続的な事前トレーニング)
  - データ準備(データキュレーション、ガバナンス、サイズ、ラベル付け、代表性、人間からのフィードバックによる強化学習(RLHF))
- **タスク3.4: 基盤モデルのパフォーマンスを評価する方法を説明する**
  - 評価手法(人間による評価、ベンチマークデータセット)
  - メトリクス: ROUGE (Recall-Oriented Understudy for Gisting Evaluation)、BLEU (Bilingual Evaluation Understudy)、BERTScore
  - 基盤モデルがビジネス目標(生産性、ユーザーエンゲージメント、タスクエンジニアリング)を満たしているかの判断

### 第4分野: 責任あるAIに関するガイドライン(14%)

- **タスク4.1: 責任あるAIシステムの開発について説明する**
  - 責任あるAIの特徴(バイアス、公平性、包括性、堅牢性、安全性、信憑性)
  - 特徴を特定するためのツールの使用方法(Amazon Bedrockのガードレールなど)
  - モデル選択における責任ある慣行(環境への配慮、持続可能性、道徳的主体性)
  - 生成AIの法的リスク(知的財産権侵害の申し立て、偏ったモデル出力、顧客の信頼喪失、エンドユーザーリスク、ハルシネーション)
  - データセットの特徴(包括性、多様性、キュレートされたデータソース、バランスの取れたデータセット)
  - バイアスと分散の影響(人口統計グループへの影響、不正確さ、オーバーフィット、アンダーフィット)
  - 検出・モニタリングのツール(ラベル品質の分析、人間による監査、サブグループ分析、Amazon SageMaker Clarify、SageMaker Model Monitor、Amazon Augmented AI (Amazon A2I))
- **タスク4.2: 透明性の高い説明可能なモデルの重要性を認識する**
  - 透明で説明可能なモデルと、そうでないモデルの違い
  - 識別のためのツール(Amazon SageMaker Model Cards、オープンソースモデル、データ、ライセンス)
  - モデルの安全性と透明性の間のトレードオフ(解釈可能性とパフォーマンスの測定)
  - 説明可能なAIのための人間中心設計の原則

### 第5分野: AIソリューションのセキュリティ、コンプライアンス、ガバナンス(14%)

- **タスク5.1: AIシステムを保護する方法を説明する**
  - AWSのサービスと機能(IAMロール・ポリシー・アクセス許可、暗号化、Amazon Macie、AWS PrivateLink、AWS責任共有モデル)
  - ソース引用とデータ出典の文書化(データリネージ、データのカタログ化、SageMaker Model Cards)
  - 安全なデータエンジニアリングのベストプラクティス(データ品質の評価、プライバシー強化技術、データアクセス制御、データの完全性)
  - セキュリティとプライバシーの考慮事項(アプリケーションセキュリティ、脅威検出、脆弱性管理、インフラストラクチャ保護、プロンプトインジェクション、保管中および転送中の暗号化)
- **タスク5.2: AIシステムのガバナンスとコンプライアンス規制を認識する**
  - 規制コンプライアンス基準(国際標準化機構(ISO)、System and Organization Controls (SOC)、アルゴリズム説明責任法)
  - 支援するAWSサービス(AWS Config、Amazon Inspector、AWS Audit Manager、AWS Artifact、AWS CloudTrail、AWS Trusted Advisor)
  - データガバナンス戦略(データライフサイクル、ログ記録、レジデンシー、モニタリング、観察、保持)
  - ガバナンスプロトコル(ポリシー、レビューサイクル、レビュー戦略、生成AIセキュリティスコーピングマトリックスなどのガバナンスフレームワーク、透明性基準、チームトレーニング要件)

## 本アプリの教材・問題集への反映方針

- **教材(aif)**: 5分野14章構成。タスクステートメント1つを原則1章に対応させる(第1分野3章、第2分野3章、第3分野4章、第4分野2章、第5分野2章)。章末確認問題は各章10問(計140問)。
- **問題集(aifbank)**: 200問。出題比率は本試験の分野比率に一致させる — 分野1: 40問(20%) / 分野2: 48問(24%) / 分野3: 56問(28%) / 分野4: 28問(14%) / 分野5: 28問(14%)。
- 並べ替え・内容一致・ケーススタディ形式の知識は択一/複数選択形式に変換して出題する。
- Foundationalレベルのため、実装詳細ではなく「概念の理解・ユースケースへのサービス/手法の対応付け・トレードオフの判断」を問う。シナリオは短め(2〜4文)にする。
